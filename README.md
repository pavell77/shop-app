## **README — shop-app (Precinct13)** 

## **Демонстраційний e-commerce проєкт на базі стабільного стеку Laravel 12.** 

Проєкт створено для професійного портфоліо, демонструючи глибоке розуміння класичної архітектури, інтеграції сторонніх платіжних систем (WayForPay SDK) та покриття коду PHPUnit тестами. 

## **Концепція проєкту** 

Цей  додаток  розроблено  як  класичний,  канонічний  інтернет-магазин  на  базі **Laravel  12  (PHP 8.3/8.4)** . Проєкт свідомо фокусується на максимально обкатаному та стабільному стеку, який зараз розгорнутий  у  більшості  комерційних  компаній  та  використовується  сотнями  розробників  на реальних продакшен-серверах. 

Тут відпрацьовано архітектурні патерни, інтеграцію реальних фінансових шлюзів, чисте логування, побудову класичних тестів та взаємодію з сесіями в стандартному Blade-середовищі. 

## **Основний технологічний стек**[7] 

- **Backend:** PHP 8.3+ / Laravel 12 

- **Frontend & UI:** Classic Blade Templates / Tailwind CSS / Vanilla JS (передбачуваний рендеринг без SPA-ускладнень) 

- **Environment:** Laravel Sail (Docker: App, MySQL, Mailpit) 

- **Testing:** PHPUnit Framework (повна ізоляція тестів, Mock-об'єкти для сервісів) 

- **Payment Gateway:** WayForPay PHP SDK (офіційна бібліотека для генерації підписів та обробки callback-запитів) 

## **Що реалізовано та обкатано в проєкті** 7 

## **1. Класична логіка кошика (Session Management)** 

- Реалізовано надійне збереження стану кошика через сесії Laravel. 

- CRUD-операції: додавання товарів, динамічна зміна кількості, видалення позицій та повне очищення. 

- Жорсткий контроль типізації для IDE через анотації `/** @var \App\Models\User $user */` . 

1 

## **2. Інтеграція WayForPay (Платіжний шлюз)** 

- Впроваджено **WayForPay PHP SDK** для формування захищених платежів та перевірки підписів (HMAC_MD5). 

- Реалізовано безпечний Webhook (Callback) контролер, який автоматично оновлює статус замовлення в базі даних після підтвердження від банку. 

## **3. Контроль доступу та Безпека** 

- Чітке розмежування гостьових сесій та авторизованих користувачів. 

- Маршрути кошика та чекауту захищені мідлверами `auth` та `verified` . 

## **4. Повне тестове покриття (PHPUnit)** 

- Написано функціональні тести (Feature Tests) для `CartController` , `ProductController` та `PaymentCallbackTest` . 

- Тести ізольовані від зовнішніх сидерів через трейт `RefreshDatabase` , активно використовують Mock-об'єкти для імітації відповідей від `WayForPayService` , гарантуючи тестування бізнеслогіки без реальних запитів до платіжної системи. 

## **`🛠️` Інструкція з розгортання (Quick Start)** 

## **Крок 1. Клонування проєкту та налаштування оточення** 

`git clone https://github.com/pavell77/shop-app.git cd shop-app cp .env.example .env` 

## **Крок 2. Встановлення залежностей (включно з WayForPay SDK)** 

**Важливо:** Проєкт використовує офіційний пакет `wayforpay/php-sdk` для обробки платежів. Переконайтеся, що composer успішно завантажив його у папку `vendor/` . 

## `composer install` 

_(Якщо SDK не було збережено в composer.json, встановіть його вручну:_ _`composer require wayforpay/php-sdk` )_ 

2 

## **Крок 3. Запуск Docker-контейнерів через Sail** 

`./vendor/bin/sail up -d` 

## **Крок 4. Ініціалізація бази даних та генерація ключів** 

`./vendor/bin/sail artisan key:generate ./vendor/bin/sail artisan migrate --seed` 

## **Крок 5. Запуск тестів** 

Перевірка працездатності всього класичного e-commerce функціоналу та мокінг платіжних колбеків через PHPUnit: 

`./vendor/bin/sail artisan test`

- **Основний сайт:** http://localhost:8080 

- **Поштовий хаб (Mailpit):** http://localhost:8025 (перевірка відправки листів після успішної оплати)
